🔎 Desafio 28 — Post 02
Transforme alertas em perguntas que ajudam a decidir

No Post 01, a inteligência artificial fez o reconhecimento inicial da planilha e apontou situações que mereciam investigação. Esta etapa começa onde o mapeamento terminou.
O objetivo agora é transformar cada alerta em uma pergunta de negócio. O exercício ajuda a separar fatos, hipóteses e decisões possíveis sem atribuir causas que os dados não conseguem provar.

🎯 Objetivos do exercício
Ao final, você deverá conseguir:
  1.priorizar os alertas mais relevantes;
  2.transformar um achado técnico em uma pergunta de negócio;
  3.separar evidência encontrada de hipótese;
  4.identificar quais dados ainda faltam;
  5.propor análises adicionais e ações possíveis;
  6.indicar o nível de confiança de cada conclusão.

📂 Arquivos necessários
Este exercício reutiliza os arquivos do Post 01:
🔸 📊 2026Base_Vendas.xlsx — base sintética que deve ser analisada;
🔸 ✅ Gabarito_2026Base_Vendas.xlsx — arquivo de conferência, aberto somente depois da análise;
🔸 🧭 criterios_de_conferencia.md — critérios para avaliar a qualidade das perguntas produzidas.

Se você salvou a resposta do exercício anterior, use-a como ponto de partida. Caso não tenha salvado, execute novamente o prompt do Post 01 antes de continuar.

Os arquivos disponibilizados neste desafio usam dados 100% sintéticos, gerados para fins educacionais. Nenhum registro foi copiado, adaptado ou extraído de clientes, empresas, projetos, ERPs ou bases públicas.

💬 Prompt
Analise o arquivo 2026Base_Vendas.xlsx como um analista de negócios.

Use os alertas encontrados no mapeamento inicial como ponto de partida. Se eu não fornecer essa análise anterior, refaça o mapeamento necessário antes de continuar.

Selecione os cinco alertas com maior potencial de impacto. Considere frequência, valor financeiro, alcance, urgência e possibilidade de ação.

Para cada alerta, apresente:
   1. Fato encontrado: descreva o achado com números, colunas utilizadas e exemplos verificáveis de linhas.
   2. Pergunta de negócio: formule uma pergunta que ajude alguém a decidir.
   3. Recortes necessários: indique quais dimensões devem ser comparadas, como produto, categoria, canal, região, estado, vendedor, cliente, transportadora ou período.
   4. Hipóteses: liste explicações possíveis, deixando claro que ainda precisam ser testadas.
   5. Evidência necessária: informe quais cálculos, cruzamentos ou dados adicionais permitiriam confirmar ou descartar cada hipótese.
   6. Ação possível: apresente até três opções de ação, sem escolher por mim e sem inventar causas.
   7. Confiança: classifique a conclusão como alta, média ou baixa e explique o motivo em uma frase.

Organize o resultado em uma tabela com as colunas:

Prioridade | Alerta | Fato comprovado | Pergunta de negócio | Hipóteses | Evidência necessária | Ações possíveis | Confiança

Depois da tabela, entregue:
  - as três perguntas que deveriam chegar primeiro à liderança;
  - uma análise adicional que pode mudar a interpretação dos alertas;
  - os dados que estão ausentes e limitam qualquer conclusão;
  - uma lista das afirmações que seriam arriscadas sem investigação adicional.

Regras:
  - não transforme correlação em causa;
  - não invente valores ou justificativas;
  - diferencie claramente fatos, hipóteses e recomendações;
  - cite os nomes exatos das colunas utilizadas;
  - informe quando o arquivo não permitir responder;
  - não altere a planilha.

✅ O que uma boa resposta deve apresentar
 🔸perguntas específicas e ligadas a uma decisão;
 🔸números e colunas que sustentem cada alerta;
 🔸hipóteses identificadas como hipóteses;
 🔸indicação clara dos dados ausentes;
 🔸ações compatíveis com as evidências disponíveis;
 🔸linguagem compreensível para alguém que não montou a planilha.

Uma pergunta ampla como “por que as vendas caíram?” ainda deixa trabalho demais para quem precisa decidir. Uma pergunta útil delimita período, produto, região, canal ou outro recorte verificável.
